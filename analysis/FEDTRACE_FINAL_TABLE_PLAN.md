# FedTrace-FM — Final Publication Table Plan (Phase P5)

**Status:** Table-generation planning/report document. `src/analysis/fedtrace_detector.py`, `src/attacks/traceability.py`, `src/federated/aggregation/multikrum.py`, every config, every result/checkpoint artifact, and `Research_Database/FedTrace_Master_Results.xlsx` were read only, never modified. ## 1. Table Design Principle (Part 1)

No single table lists all 27 experiments in the main paper. The main-paper set (5 tables) is organized by evidentiary role — setup, frozen validation, ablation, external baseline, targeted generalization — each answering one specific reviewer question. The complete `EXP_001`–`EXP_027` registry, the qualitative method-evolution history, and detailed utility metrics live in three appendix tables. A reader can follow the paper's central claim end to end from the five main tables alone.

## 3. Per-Table Notes

**Table 1 (setup):** performance metrics are deliberately excluded — this table is configuration only, sourced from `EXP_018`'s own config file plus `EXP_020`'s round-0 `multikrum_diagnostics.csv` for a live-derived Multi-Krum `f`/`m` (rather than asserting `f=1`/`m=4` from memory: `f = n_clients − selected_count`, `m = selected_count`, both counted directly from the artifact). `τ`, `P`, `T_ref` are read directly from `src/analysis/fedtrace_detector.py`'s own module constants (`DEFAULT_THRESHOLD`, `DEFAULT_PERSISTENCE`, `DEFAULT_T_REF`), not retyped.

**Table 2 (frozen validation):** restricted to `EXP_016`–`019` only, exactly as instructed — `EXP_014`/`015` (development runs) are excluded by construction (the table's row list is a fixed 4-tuple, not derived from any "all attack runs" query that could accidentally include them). Every cell is computed live via `ft.evaluate_detector_v3`. **A defect was found and fixed during generation**: the initial "Dominant signal" computation counted every round (including the documented pre-attack round-0/round-1 self-inclusive calibration artifact — see `analysis/FEDTRACE_MASTER_RESEARCH_STATUS.md` §7), producing a misleading "mixed" result for all four rows instead of the correct, previously-published per-run dominance. **Fixed** by restricting the dominant-signal count to `round_id ≥ attack_start_round` (the genuinely attack-driven window), matching the exact methodology already used in every `EXP_016`–`019`/`026`/`027` analysis document. After the fix, all four rows match the published Stage B synthesis exactly (`EXP_016`: `z^m` 30/30; `EXP_017`: mixed `z^m` 10/30 / `z^t_res` 20/30; `EXP_018`/`019`: `z^t_res` 30/30). The "First anomaly = 0" artifact is **not hidden** — it is shown in its own column and explicitly explained in the table's footnote, per this project's standing "report, don't hide" discipline for this exact artifact. No mean/std summary row is added (n=2 seeds per family does not support a pre-registered summary statistic, per this table's own footnote and `analysis/FEDTRACE_MASTER_RESEARCH_STATUS.md` §4/C9).

**Table 3 (signal ablation):** rows = peer-only, magnitude-only, temporal-residual-only, full FedTrace v3 (magnitude + temporal-residual explicitly, matching v3's actual combiner — "magnitude + peer" and other v1-era combinations were not re-added here, since v3's frozen combiner is `max(z^m, z^t_res)` only, not a 3-signal combination; the peer signal is shown only as its own standalone row, per its already-established "never contributes" status). Every cell computed live via the frozen module's `evaluate_detector`/`evaluate_detector_v3` with the stated component subset. **Caption/footnote uses "coverage, not fusion" language explicitly, matching the task's required framing** — the full-detector row never shows a strictly better onset-error/delay than its best individual component in any of the four runs, and the footnote states this directly.

**Table 4 (Multi-Krum baseline):** the central external-baseline table, `EXP_020`–`025`. Attacker rejection rate and the persistent honest rejected client are both computed fresh from each run's own `multikrum_diagnostics.csv`; the "Proxy predicted client" column applies the same `P_krum=3` persistence rule already used in `Research_Database/sync_master_results.py` (Phase P2) directly to the raw diagnostics, not read from the workbook (avoiding a stale-snapshot dependency while remaining consistent with it — cross-checked and found identical). **The footnote explicitly states the proxy is "repurposed... not a native attribution method,"** per the task's precision requirement. The FedTrace column reports the paired FedAvg run's own (correct) attribution, making the "successful exclusion ≠ correct attribution" contrast visible within a single row.

**Table 5 (generalization, replacing Figure 8):** `EXP_018`/`026`/`027`, each computed live via the frozen detector, with an internal `TableDataError` guard that would halt generation if a row's live-computed result ever deviated from the expected all-criteria-PASS pattern (it did not — all three rows pass). **Footnote states explicitly: "one targeted test per axis is evidence of generalization within that one comparison, not a claim of arbitrary-client or arbitrary-onset invariance"** — verbatim scope language, matching Part 12's required framing.

**Table A1 (full registry):** a compact reformatting of `analysis/FEDTRACE_EXPERIMENT_REGISTRY.csv` (27 rows, `EXP_001`–`027`). `EXP_013` is shown with `Category=SUPERSEDED (decision-only...)`, `Final Top-1 = NOT RECORDED`, and every other quantitative field `NOT APPLICABLE` — never fabricated.

**Table A2 (method evolution):** the only table in this package that is not derived from a single numeric artifact field, since it is a qualitative development-history narrative. Content is a small, explicitly-cited transcription from `analysis/FEDTRACE_STAGE_A_RETROSPECTIVE_ANALYSIS.md`, `analysis/FEDTRACE_V2_RETROSPECTIVE_ANALYSIS.md`, and `analysis/FEDTRACE_V3_RETROSPECTIVE_ANALYSIS.md` (all re-read during Phase P3 and re-verified against the specific rounds/counts cited), matching the same "explicit, cited constant table" discipline already used in `Research_Database/sync_master_results.py`'s `FEDTRACE_ATTRIBUTION_FACTS` (Phase P2). Footnote states directly: "v1 and v2 are shown to explain why v3's calibration design was necessary, not as competing final methods."

**Table A3 (utility metrics):** restricted to the centralized reference plus the main FedAvg/Multi-Krum/generalization experimental groups (15 rows) — not every historical experiment; `EXP_002`–`007`/`010`–`015` remain covered only by Table A1, per the task's own "include only experiments necessary" instruction.

## 7. Defects Found and Fixed During This Task

- **Table 2/Table 5 "Dominant signal" computation:** initially counted every round (0–49) rather than only post-onset rounds, causing the documented round-0/round-1 pre-attack calibration artifact to contaminate the dominance tally and produce a misleading "mixed" result for every row. **Fixed** by restricting the count to `round_id ≥ attack_start_round`; re-verified against already-published values (§3, §6-4) after the fix.
- **Registry sentinel-value mismatch:** `analysis/FEDTRACE_EXPERIMENT_REGISTRY.csv` uses `NOT_APPLICABLE`/`NOT_RECORDED` (underscore) while this script's own constants use `NOT APPLICABLE`/`NOT RECORDED` (space); Table A1's Top-1 formatting crashed on `EXP_013`'s sentinel value on first run. **Fixed** with a defensive `try/except float()` conversion rather than an exact-string match.
- **Wide-table LaTeX overflow:** Table 2 (14 columns) and Table 4 (13 columns) would not fit a single ICML/ICLR column. **Fixed** by adding an automatic `wide` mode (triggered at ≥12 columns) that wraps the tabular in `\resizebox{\textwidth}{!}{...}` inside a `table*` environment.

No other defect was found on inspection.
