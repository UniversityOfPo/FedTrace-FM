## 1. Observation model

Synchronous FedAvg, K clients, full participation, rounds r = 0, 1, …. The server broadcasts θ_r; client k returns
the state u_k(r) = θ_r + Δ_k(r), with

    Δ_k(r) = T_k(θ_r, D_k(r), ξ_k(r)),

T_k the local procedure (the prescribed T for an honest client), D_k(r) the data used in round r, ξ_k(r) local
randomness independent across clients. θ_{r+1} = θ_r + Σ_k p_k Δ_k(r).

Server information at the end of round r (plaintext aggregation, as in all FedTrace runs):
O_r = {θ_s, u_k(s) : s ≤ r, k = 1..K} plus any server-held auxiliary data A (none in FedTrace so far). The server never
sees D_k, ξ_k, labels or T_k. Under secure aggregation O_r reduces to {θ_s}; per-client statements A–D below are then
impossible without group designs (FedGT, checklist §A3).

Behaviour of client k is the conditional kernel 𝒦_k,r(· | θ) = law of Δ_k(r) given θ_r = θ. The server sees one draw
per round, at a θ that is itself different every round.

## 2. Four distinct problems

| | Problem | Formal target |
|---|---|---|
| A | Change detection | Does 𝒦_k,r change at some τ_k (𝒦_k,r = 𝒦_k,pre for r < τ_k, ≠ afterwards)? |
| B | Source of a shared-reference disturbance | Which client's kernel changed first, S = argmin_k τ_k, given that other clients' observations move after it? |
| C | Malice | Is client k's post-change behaviour generated by an adversarial process rather than an admissible benign one? |
| D | Attack onset | τ_S, the first round of malicious behaviour of the source |

Detection is not attribution (A ≠ B), and attribution of a change is not attribution of malice (B ≠ C). D is defined
only once C is: as a change-point, τ_S is the onset of a change, not of malice.

## 3. Results

### Lemma 1 (dynamic coupling: honest observations change after the source changes)

If client j changes at τ, then θ_{τ+1} depends on Δ_j(τ), so for an honest k with unchanged kernel the law of
Δ_k(τ+1) = T(θ_{τ+1}, D_k, ξ) generally differs from its counterfactual. Any test of *marginal* stationarity of an
honest client's observations (norm, self-cosine, residuals, CUSUM, z-scores) therefore has a valid reason to fire after
τ + 1 even with a perfect reference. Contamination is not only an artefact of the inclusive median (L-56, L-66); a
second channel runs through the global model and no choice of cross-client reference removes it. (In the FedTrace runs
the norm-based own-history detectors did not accuse honest clients in any attacked run, L-69, suggesting this channel
was weak for that feature; its size was not quantified separately.)

### Lemma 2 (temporal precedence at the change round; exact)

Under synchronous FedAvg, honest submissions in round τ are functions of (θ_τ, D_k, ξ_k(τ)), and θ_τ depends only on
submissions before τ. Hence, if the first kernel change occurs at τ in client j only, then for every k ≠ j the joint
law of {u_k(s) : s ≤ τ} is identical to the no-change law. Empirically confirmed: honest round-20 submissions are
bit-identical to the matched clean run in every arm (L-63 and the prefix checks).

Consequences: (i) the source of a single first change is identifiable *in principle* as the only client whose own
statistics change at τ; (ii) any statistic that mixes the current round across clients (the inclusive median in v3)
destroys this precedence by moving honest residuals at τ itself; (iii) in practice the precedence has a one-round
margin, while change-time estimates from persistent statistics are off by 0–8 rounds (norm z-score / CUSUM onset
estimates 20–21, L-56; v3 onset estimate 28 for seed-123 BadNets, L-69 matrix) and confirmation needs ≥ 2 further
rounds, so the resolution — not identifiability — is the binding problem; (iv) simultaneous first changes (collusion, or common-mode server
events such as a learning-rate step) are not separable by precedence.

### Proposition 3 (observational equivalence of data poisoning and benign data; rigorous)

Let a malicious client run the prescribed T on a dataset D′ (data poisoning: BadNets, relabel-only). If the
admissible benign class 𝔅 contains a benign process that produces the same data D′ in the same rounds — for example a
client that genuinely holds or collects D′ — then the laws of the entire observation sequence under the two
hypotheses are equal: P_M = P_B on O_R for every R (same T, same data, same θ trajectory, same randomness law). By Le
Cam's inequality, every test φ satisfies

    P_B(φ = 1) + P_M(φ = 0) ≥ 1 − TV(P_B, P_M) = 1,

so no server-side procedure using O_R does better than chance at C. Malice of a data-poisoning client is therefore
identifiable only relative to an assumed restriction on 𝔅, never from the updates alone. (For model poisoning,
T′ ≠ T, the update need not be producible by T on any dataset; FedREDefense's reconstruction principle exploits this,
but its paper excludes data poisoning, §A2.)

This is a statement about a specified pair of processes, not a universal impossibility theorem: it shows that every
positive result about C must name the restriction on benign data that excludes D′ and defend that restriction.

### Restrictions that could make C identifiable (threat-model assumptions, not observations)

| ID | Restriction on honest data | Makes identifiable | Violated by (benign) |
|---|---|---|---|
| R1 | Labels follow a common labelling function: honest p_k(y∣x) = p*(y∣x); honest heterogeneity and drift are changes of p_k(x) or p_k(y) only (covariate / label shift) | relabel-only (conditional shift); the label-flip part of BadNets | label noise, annotation-policy differences, genuinely different label semantics, fine-grained ambiguity |
| R2 | Honest data contain no small input pattern predictive of one class | the trigger part of BadNets | natural shortcuts (watermarks, logos, sensor artefacts) |
| R3 | Honest data are stationary | any change | **rejected**: benign drift is admissible (P-35) |

### Onset (D)

τ_S is identifiable as a change-point of the source's kernel only under honest-before-onset, a clean calibration
window, distinct pre- and post-change laws, and a model of how the kernel depends on θ (Lemma 1); its resolution is
bounded below by the one-round precedence margin and above by the per-round signal-to-noise (one draw per round,
lag-1 autocorrelation 0.82–0.91, L-61). Onset of *malice* is identifiable only to the extent C is (Proposition 3).

## 5. Candidate directions (ranked by scientific defensibility; none selected or implemented)

### Direction 1 — Label-shift-invariant conditional-shift attribution (E1 + E3)

1. **Question.** Can a server holding unlabelled in-distribution probe inputs separate client changes explainable as
   class-prior (label) shift from changes of the client's conditional decision function, using only submitted
   models, and localize the first such change in time?
2. **Principle.** Under label shift the Bayes posterior obeys p′(y∣x) = w(y) p(y∣x) / Σ_c w(c) p(c∣x) for a class-only
   weight vector w. Project the client model's probe posteriors onto this family relative to the pre-round global
   model (a convex fit of w per update, not a threshold on outcomes); the residual divergence is evidence of a
   conditional (concept) shift; its first change on the client's own history (Lemma 2) estimates the onset.
3. **Assumptions.** R1; probes from the task distribution (labels never used); finite local training under label
   shift behaves approximately like prior reweighting; full participation; honest-before-onset.
4. **Difference from prior work.** Probe-based defences score loss / accuracy / indicator tasks and treat any
   deviation as suspicious; DeepSight estimates label distributions and treats homogeneity as suspicious; none found
   (§A3, §A4) declares label shift the benign null and attributes only the residual. The label-shift identity itself
   is established (BBSE).
5. **BadNets.** Residual expected from the relabelled component on clean probes; the trigger-specific change lives on
   inputs absent from clean probes → partial sensitivity.
6. **Relabel-only.** Conditional change on source-class inputs → x-dependent, not class-reweighting-explainable →
   large residual expected.
7. **Benign class drift (correct labels).** Pure label shift by construction (X4: class composition only) → small
   residual expected **if** assumption 3 holds; the key falsification point.
8. **Norm-matching.** Scaling shrinks the posterior change but cannot remove the conditional change without losing
   the attack; residual reduced, not eliminated. A probe-aware adaptive attacker is the main threat (blind spot).
9. **Onset.** Yes, via own-history change on the per-round residual (Lemma 2), with the resolution limits of §3.
10. **Main falsification test.** On the existing development logs (CPU): if the drift residual is not smaller than the
    relabel-only residual of the same seed, the finite-training label-shift approximation fails and the principle is
    falsified for this setting (criteria to be frozen before computation).
11. **Cost.** CPU proof of concept ≈ 8 runs × 35 rounds × 6 models ≈ 1,700 model evaluations × ≈ 3.5 s (1,000
    probes) ≈ 1.7 CPU-h plus fitting (< 1 h). No GPU. Later confirmation needs new benign types (label noise,
    new-class acquisition) ≈ 2.4 GPU-h per matched pair.
12. **Novelty risk.** Moderate: combination of an established label-shift identity with probe-based FL scoring;
    the probe-data assumption is FLTrust-like; label noise is an obvious benign counterexample (R1 violated).

### Direction 2 — Precedence-based source and onset localization (E3; analysis contribution)

1. **Question.** How much of B and D is identifiable from the one-round propagation lag of synchronous FedAvg, and
   what is the attainable resolution under realistic per-round noise and dynamic coupling?
2. **Principle.** Lemma 2: at the change round only the source's submissions change in law; downstream changes begin
   ≥ τ + 1. Statistics must use other clients' information only from rounds < τ.
3. **Assumptions.** Synchronous rounds, full participation, single first changer, honest-before-onset, clean
   calibration.
4. **Difference.** FLTracer and FLDetector use per-client cross-round evidence but (in the parts read) state no
   precedence identification result or resolution bound; v3's inclusive reference violates precedence.
5–7. **BadNets / relabel-only / drift.** Localizes the source of *a change* equally in all three; says nothing about
   malice (by design).
8. **Norm-matching.** Depends on the remaining channels; precedence is feature-agnostic.
9. **Onset.** Yes; central.
10. **Falsification.** On existing logs, quantify honest clients' deviation from the counterfactual at τ + 1, τ + 2,
    … (diagnostic): if honest deviation at τ + 1 is comparable to the source's at τ, the precedence margin is
    unusable in practice.
11. **Cost.** CPU minutes on existing traces / logs. No GPU.
12. **Novelty risk.** High as a method (change-point attribution, FLTracer); defensible only as a formal analysis
    component.

### Direction 3 — Server-side trigger inversion on client models (E2)

1. **Question.** Does a client update create a small universal input perturbation to one class that the pre-round
   global model does not have?
2. **Principle.** R2 (shortcut minimality, Neural Cleanse family) applied to Δ_k.
3. **Assumptions.** R2; probe images; patch-like triggers.
4. **Difference.** FLIP inverts client-side; server-side per-update inversion with onset tracking — novelty UNVERIFIED.
5. **BadNets.** Detectable (3×3 patch).
6. **Relabel-only.** Not detectable (no trigger).
7. **Benign drift.** No trigger expected; natural shortcuts are the false-positive risk.
8. **Norm-matching.** Unaffected in principle.
9. **Onset.** Yes, per round, at high cost.
10. **Falsification.** Inversion norm under drift vs BadNets on existing logs.
11. **Cost.** Optimisation per client-round; CPU tens of hours for the existing logs; GPU preferable.
12. **Novelty risk.** High (Neural Cleanse lineage; FL variants not fully verified).

## 6. Threat-model and novelty risks

- **FLTracer** already claims online per-client attribution with attack time and type, cross-round per-client
  modelling, classifier-weight evidence for dirty-label attacks and handling of gradual drift; FedTrace cannot claim
  attribution + onset as new without a direct comparison. Its stated sacrifice of abruptly shifting benign clients is
  the clearest gap that a benign-drift-safe method would address.
- Proposition 3 makes any "malicious attribution" claim conditional on R1 / R2; a CVPR submission must state the
  restriction up front.
- Direction 1 introduces a server-held probe set (threat-model change).
- All directions were formulated after seeing the development runs; any evaluation needs fresh benign types and new
  seeds; the sealed confirmation seeds stay unused until a protocol is frozen.

## 8. Amendment 1 — 2026-10-25 (Prompt 31 review; supersedes §§1–3 and the R1 row where they differ)

### A1. Observation model (corrects §1)

- A submission is a **full model state** u_k(r) (all floating parameters and BatchNorm running statistics, plus
  `num_batches_tracked`), not a delta; the delta Δ_k(r) = u_k(r) − θ_r is computed by the server over the floating
  keys. FedAvg averages **every floating tensor including BN running statistics**, weighted by the declared sample
  counts p_k = n_k / Σ n (`src/federated/aggregation/fedavg.py`); the server therefore also observes n_k.
- The server holds the pre-round global state θ_r exactly (logged; θ_r = global after round r − 1, θ_0 = initial).
- Under the probe-augmented threat model (P-43) the server additionally holds an unlabelled image set A, fixed before
  training and disjoint from every client's data and from final evaluation. Labels of A are never an input.
- O_r = {θ_s, n_k, u_k(s) : s ≤ r, all k} ∪ {A}. Nothing about D_k, ξ_k, T_k or labels is observed.

### A2. Hypothesis classes (formalises §§2–3)

A client process is a pair (training map T, data process D = (D(r))_r). Honest class
H_B(𝔅) = {(T, D) : T prescribed, D ∈ 𝔅}, where 𝔅 is the admissible benign data class; malicious class
H_M = {(T′, D′) with an adversarial objective}, split into data poisoning (T′ = T) and model poisoning (T′ ≠ T).
The *observation law* P_{(T,D)} is the law of O_R induced by that client's process together with fixed processes for
all other clients, the server, the seeds' distribution and A.

### A3. Identical-observation-law argument (restates Proposition 3 precisely)

If (T, D′) ∈ H_M is a data-poisoning process and D′ ∈ 𝔅, then (T, D′) ∈ H_B as well: the two hypotheses contain a
common process, and its observation law is literally the same object under both labels. "Malicious" vs "benign" is
then not a property of the law of O_R. For two specific processes M = (T, D′) and B = (T, D_B) with D_B ≠ D′ the laws
are equal only if the induced update sequences have the same joint law (same n_k, same round-wise data laws as seen
through T, same randomness law); equality of data is sufficient, not necessary.

### A4. When Type I + Type II ≥ 1 holds (corrects the scope of §3)

For a simple pair (P_B, P_M) and any test φ based on O_R: P_B(φ = 1) + P_M(φ = 0) ≥ 1 − TV(P_B, P_M)
(Neyman–Pearson / Le Cam two-point bound). The sum is ≥ 1 for **every** test **iff TV = 0**, i.e. exact equality of
the two laws on the σ-field generated by O_R. For composite hypotheses the bound holds with
inf over (B ∈ H_B, M ∈ H_M) of TV, which is 0 whenever the classes share a law (A3). Consequences: (i) the result is
conditional on the chosen 𝔅 and on the observation σ-field (adding A, or TEEs, changes it); (ii) with TV > 0 but
small, errors are bounded below by 1 − TV, not by 1; (iii) **it does not show that malicious intent is universally
unidentifiable**: under a restricted 𝔅 (R1 / R2) that excludes D′, the bound is vacuous and identification may be
possible; it shows only that any positive result must state and defend such a restriction.

### A5. Label, covariate and concept shift (corrects R1 in §3 — the original R1 was internally inconsistent)

With p(x, y) = p(y) p(x∣y) = p(x) p(y∣x):

| Shift | Changes | Fixed | Bayes posterior p(y∣x) |
|---|---|---|---|
| Label (prior) shift | p(y) | p(x∣y) | changes by a class-only reweighting (identity in Task 2 / protocol 16) |
| Covariate shift | p(x) | p(y∣x) | unchanged on the common support |
| Concept shift | p(y∣x) (or p(x∣y) with p(y) fixed, "conditional shift") | — | changes in an x-dependent way |

The original R1 ("honest p_k(y∣x) = p*(y∣x); drift = change of p(x) or p(y)") is wrong: under label shift p(y∣x)
**does** change. Corrected **R1′**: honest clients share the class-conditional laws, p_k(x∣y) = p*(x∣y), and honest
heterogeneity / drift is a change of p_k(y) only. Covariate shift is a different null (w ≡ 1 ideally) and is **not**
covered by Direction 1. Relabel-only poisoning is concept shift on the poisoned inputs; BadNets is concept shift on
the trigger region plus the relabelled samples.

### A6. Assumptions for precedence (formalises Lemma 2)

Lemma 2 holds exactly under: (P1) synchronous rounds with every scheduled client's submission computed from the same
broadcast θ_r; (P2) full participation in rounds τ − 1 and τ (otherwise a client's first observed change can lag its
true change); (P3) client training depends only on (θ_r, own data, own randomness), with no client-to-client channel;
(P4) client randomness independent across clients and of the source's change; (P5) no server-side change at τ
(aggregation rule, learning-rate schedule, client set); (P6) exactly one client's kernel changes at τ. Then for k ≠ j
the law of (u_k(s))_{s ≤ τ} is the no-change law (with fixed seeds, the realisations themselves coincide — observed
bit-exactly, L-63).

### A7. Limitations (extends §3)

- **Multiple simultaneous changes** (colluders, a common benign event, a server-side change): precedence identifies
  only the set of first changers, not one source, and cannot separate a common-mode cause from coordinated clients.
- **Dynamic coupling** (Lemma 1): from τ + 1 every client's update law may change; persistence-based statistics
  aggregate over rounds where coupling operates, so their change-time estimates mix source and response.
- **Single draw per round**: precedence is a one-round margin; detecting the change within the first round requires a
  per-round effect large relative to per-round noise; slow ramps have no identifiable first round at this margin.
- **Partial participation / asynchrony** break P1–P2.
