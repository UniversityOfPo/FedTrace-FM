# FedTrace-FM — Research Database

## Folder Purpose

`Research_Database/` is the **permanent, cross-experiment record** for the
FedTrace-FM project. Where `experiments/EXP_XXX_*.md` files document one
experiment each in narrative form, and `RESEARCH_DIARY.md` records the
chronological story of each work session, this folder is the **structured,
tabular** counterpart: one row per experiment, one row per figure, one row
per paper table, aggregated across the entire project's lifetime. It is
the single place a future paper-writing session (or a future AI/human
collaborator) goes to answer "what experiments exist, what did they use,
and what did they produce" without re-reading every individual experiment
file.

This folder is built once, here, and then **appended to** — never
rebuilt from scratch — as new experiments complete.

## Contents

- **`FedTrace_Master_Results.xlsx`** — the **main, human-readable master
  workbook**. This is the file a person opens to browse results across
  every experiment: one sheet each for Experiment Summary,
  Hyperparameters, Hardware, Federated Results, Attack Results,
  Attribution Results, Paper Tables, and Notes (see
  `FedTrace_Master_Results.md` for the full per-sheet schema). It was
  added directly to this folder (not generated by any script in this
  repository) and must not be recreated or overwritten by tooling.
- **`FedTrace_Master_Results.md`** — specification for the master results
  workbook: the exact sheet/column schema, and the relationship between
  the workbook and its CSV source tables.
- **`FedTrace_Master_Results/`** — one CSV per workbook sheet
  (`01_Experiment_Summary.csv` through `08_Notes.csv`). These are the
  **structured source tables**: the authoritative, plain-text data that
  the workbook's sheets are populated from. When adding a new experiment,
  update these CSVs first (see **Workflow** below).
- **`Experiment_Index.csv`** — the master experiment registry: exactly one
  row per experiment ever run in this project.
- **`Figure_Index.csv`** — exactly one row per figure/plot ever generated
  by any experiment.
- **`Table_Index.csv`** — exactly one row per table intended for use in a
  paper. Currently empty (header only) — no paper tables have been
  authored yet (paper writing is Phase 8, not started).

**Relationship between the CSVs and the workbook:** the eight CSV files
under `FedTrace_Master_Results/` are the structured source tables — the
place new rows are actually authored. `FedTrace_Master_Results.xlsx` is
the human-readable master workbook derived from them. Future automation
(explicitly deferred — see **Update Rules**) will update the CSV source
tables from experiment outputs and then regenerate/synchronize
`FedTrace_Master_Results.xlsx` to match. Until that automation exists,
whoever adds a new experiment updates the CSVs, and the workbook is
refreshed from them as a separate, explicit step.

## Workflow

For every future experiment, once it has completed and been documented in
its own `experiments/EXP_XXX_*.md` file (per the project's existing
documentation practice):

1. Add **exactly one row** to `Experiment_Index.csv`.
2. Add **exactly one row** to `FedTrace_Master_Results/01_Experiment_Summary.csv`.
3. Add **exactly one row** to `FedTrace_Master_Results/02_Hyperparameters.csv`
   and `FedTrace_Master_Results/03_Hardware.csv`.
4. If the experiment is federated, add **exactly one row** to
   `FedTrace_Master_Results/04_Federated_Results.csv`. If it involves an
   attack, add a row to `05_Attack_Results.csv`. If it involves
   attribution, add a row to `06_Attribution_Results.csv`. These three
   sheets are not mutually exclusive — an attack+attribution experiment
   gets one row in each relevant sheet, all sharing the same
   `Experiment_ID`.
5. For every new figure the experiment produced, add **exactly one row**
   to `Figure_Index.csv`.
6. If and when a result from the experiment is used in a paper table, add
   **exactly one row** to `Table_Index.csv` (and, at that point, one row
   to `FedTrace_Master_Results/07_Paper_Tables.csv`).
7. Optionally, add one row to `FedTrace_Master_Results/08_Notes.csv` for
   any observation worth surfacing at a glance without opening the full
   experiment file.

## Update Rules

- **One row per entity.** Every experiment gets exactly one row in
  `Experiment_Index.csv` and in `01_Experiment_Summary.csv`. Every figure
  gets exactly one row in `Figure_Index.csv`. Every paper table gets
  exactly one row in `Table_Index.csv`. Do not merge multiple experiments
  into one row, and do not split one experiment across multiple rows in
  the same sheet.
- **Append-only.** Like `RESEARCH_DIARY.md`, existing rows are not
  rewritten as understanding changes. If an experiment's documented result
  turns out to be wrong (e.g., a bug is found after the fact), add a note
  explaining the correction rather than silently editing the original
  row's numbers — the original row is what was actually verified at the
  time.
- **Verified data only.** Every value entered here must trace back to an
  actual file in the repository (a `summary.json`, `round_history.csv`,
  `final_test_metrics.json`, `run.log`, or the `experiments/EXP_XXX_*.md`
  file that already verified them) — never estimated, interpolated, or
  invented. If a field is not yet known for an experiment, leave it blank
  rather than guessing.
- **Required fields for every experiment row** (`Experiment_Index.csv` and
  `01_Experiment_Summary.csv`): Experiment ID, Git Commit, Configuration
  (path to the YAML config used), Dataset, Seed, Runtime, Output folder,
  Checkpoint folder, Result status, Notes.
- **Git commit is the commit whose committed code/config actually
  reproduces the result**, not necessarily the commit active at the exact
  moment the run was started (e.g., if a result was produced from a
  working-tree change that was committed shortly afterward, record that
  later commit).
- **No automation yet.** As of this session, there is no script that
  auto-populates the CSV source tables from experiment outputs, and no
  script that regenerates/synchronizes `FedTrace_Master_Results.xlsx`
  from them. Rows are added to the CSVs by hand (by a human or an AI
  assistant, following this workflow) until such automation is explicitly
  requested and built. Future automation, once built, will read
  experiment outputs to update the CSV source tables and then
  regenerate/synchronize the Excel workbook from those tables — the CSVs
  remain the authoritative data; the workbook is always derived from them.
- **This folder is documentation, not code.** No file here is imported or
  read by any Python module in `src/`; nothing in `src/` depends on this
  folder's existence or contents.
